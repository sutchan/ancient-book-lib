# ancient-book-lib（古籍通 AncientBook）长期记忆

- **仓库**：`https://github.com/sutchan/ancient-book-lib.git`，owner = sutchan；当前分支 main。
- **技术栈**：Next.js 14 + React 18 + TypeScript，纯静态 SSG（`output: "export"`，产物 `out/`）。无数据库、无后端接口、无 ESLint 配置、无测试框架；类型检查门禁为 `npx tsc --noEmit`；`next start` 不适用于 export 模式，预览用 `npx serve out`。
- **目录（实际）**：根级 `app/ components/ lib/ scripts/ prototype/ docs/ public/` 与 `.github/`。注意 `docs/02-架构与开发规范/项目目录结构规范.md` 仍写 `src/app` 旧结构，与实际不符。
- **数据单一源（v1.3.0 起重构）**：真实书目数据来自 `garychowcmu/daizhigev20`（殆知阁 v20）。`npm run build:catalog` 调 GitHub Trees API 生成 `public/index/daizhige-catalog.json`（15,694 部，含 `rawUrl` 直链 + jsDelivr/statically 镜像）；阅读时按需 fetch，本仓库零 TXT 复制。**旧的 `lib/data-generated.ts`（45 部手写 demo）与 `scripts/build-index.mjs` 已在 v1.3.0 删除**，`app-data.js` 仅作 `prototype/` 遗留演示残留（非运行代码）。
- **人物 / 关系（v1.3.1 起数据驱动）**：`components/CharacterList.tsx` / `RelationClient.tsx` 改为读取 `public/index/characters.json` / `relations.json`（v1.3.1 新建空种子，作为数据契约），为空时回退「待接入」空态；**数据源（CBDB / ctext / 自建）尚未确定**，待用户指定后写 ingest 脚本填充并 `git add` 这两个文件（当前 untracked，生产需提交才能部署）。
- **架构红线**：禁数据库、禁后端检索、禁动态 SSR、禁直读超大原文（必须 Range 分片）、禁服务端存用户数据、古籍原文保真。
- **全文索引与章节清单生成（v1.3.1 起）**：`npm run build:fulltext`（4.9GB 上游下载）在同一次 pass 生成 `public/index/fulltext-index.json`（倒排索引）与单文件 `public/index/chapters.json`（`{bookId:[{title,start,end}]}` 章节 UTF-8 字节偏移，供超大书 Range 分片懒加载）。二者体积大、**已 gitignore、不入库**，由部署构建期生成。`.github/workflows/deploy.yml` 已加入该步骤；**但生产站（EdgeOne Pages）独立构建，必须将其构建命令设为 `npm run build:fulltext && npm run build` 才能产出索引/章节清单**，否则生产全文检索回退标题、Range 分片不生效。
- **章节识别规则（v1.3.1 修正）**：`lib/chapterParse.ts` 章节标题正则须含「品第X / 第X品」（佛经/子书，如 序品第一、寿量品第二），且上下文校验放宽为「标题后接缩进正文或空行、或上行为空行」（原要求两侧空行会漏检此类无空行分隔格式）。
- **分析（埋点）已获所有者显式授权**：原红线含「禁广告/付费/注册/埋点」，但 owner 于 2026-09-08 前明确接入 **Google Analytics 4（衡量 ID `G-H76XG9L6FZ`，IP 匿名化、仅聚合访问统计）**，覆盖原「禁埋点」约束。实现见 `app/GoogleAnalytics.tsx`（next/script afterInteractive 注入 gtag）+ `app/layout.tsx` 挂载；版本号读 `process.env.NEXT_PUBLIC_GA_MEASUREMENT_ID` 可覆盖。README 第 14–15 行已改为「不收集个人隐私（仅匿名访问统计，GA4）」。后续不再就该冲突二次提示用户。
- **文档体系**：`docs/` 八大分类（01 基础说明 / 02 架构与开发规范 / 03 PRD / 04 任务清单 / 05 设计规范与原型 / 06 部署与迭代 / 07 环境搭建手册 / 08 技术方案研究）+ 根 `README.md` + `CHANGELOG.md`。
- **社区健康文件**：位于 `.github/`（CONTRIBUTING / CODE_OF_CONDUCT / SECURITY / SUPPORT / PR 模板 / Issue 模板）。禁止创建 `.github/readme.md`。
- **生产站点**：https://guji.ewuse.com/ ，托管于腾讯云 **EdgeOne Pages**（响应头 `server: edgeone makers`，DNS 多 A 记录智能解析；由 EdgeOne 从 Git 拉取并构建 `out/`）。GitHub Pages 仅为可选备用，非生产链路——不启用 Pages 时 `actions/deploy-pages@v4` 会持续报 `Failed to create deployment (status: 404)`，属预期。
- **仓库可见性**：2026-09-08 由私有转为**公开**（`GET /repos/sutchan/ancient-book-lib` → 200 / `private:false`）。此前 Pages 无法启用的根因即仓库私有（免费计划不支持私有库 Pages）。
- **GitHub Actions 策略（v1.2.1 起）**：`.github/workflows/deploy.yml` 默认只做 CI（build:index → build:catalog → next build → 单测 → `upload-artifact@v4` 留存 out/ 7 天）；Pages 部署由仓库变量 `ENABLE_PAGES=true` 开关控制，默认关闭。仓库未启用 Pages 时 `deploy-pages@v4` 必报 `Failed to create deployment (status: 404)`，属预期误报。
- **品牌资料（v1.2.2 起）**：源图为 `public/brand/logo-source.jpg`（2048×2048，米色纸底 + 朱红方印 + 黑色「古籍通 / AncientBook」横版，比例 2.692:1；原 `public/images/logo.png` 实为 JPEG，已修正为透明 PNG）。生成脚本 `scripts/brand/*.ps1`（Windows GDI+，零第三方依赖，`powershell -File scripts/brand/build-brand-assets.ps1`），产物在 `public/brand/`，接入位为 `app/icon.png`、`app/apple-icon.png`、`app/opengraph-image.png`、根 `favicon.ico` / `apple-touch-icon.png` / `site.webmanifest`；**生成产物禁止手改**。品牌主色 `#A93320`、纸色 `#F7F3EA`（与 UI `--color-primary:#8C3130` 不互相覆盖）。规范见 `docs/05-设计规范与原型/品牌资料使用规范.md`。
- **环境与工具链坑**：无 sharp/pngjs/PIL；PowerShell 脚本必须 UTF-8 BOM 否则中文乱码；IDE 的 safe-delete shim 会让 `fs.rmSync('.next')` 报 trash 错误，重跑 build 即可。
- **原型脚本结构（v1.3.2 起）**：单文件 `prototype/assets/prototype.js`（821 行）已删除，拆为 `prototype/assets/js/` 下 10 个按 `<script>` 顺序加载的经典脚本（非 ES module，保证 file:// 直开）：`t2s-map` → `core` → `view-home` / `view-read` / `view-search` / `view-character` / `view-relation` / `view-help` / `view-stats` → `boot`，共享全局命名空间 `window.AB`（`AB.DATA/state/$/$$/esc/toSimplified/save/getMain/renderX`）。11 个 HTML（prototype.html + pages/*.html）已同步引用。内联 onclick 用 `AB.openBook(id)` / `AB.filterBooks(name)`，**不可引用 IIFE 私有变量**（原 `state.currentBookId=...` 会 ReferenceError）。
- **原型演示标识与存储兜底（v1.3.5 起）**：原型数据（45 部演示书目 / 派生人物 / 通用样张正文）与正式站点不同源，故 ① `core.js` 的 `renderPrototypeNotice()` 用 JS 动态注入顶部「原型」提示条（boot 中调用，11 个页面免改 HTML）；② 仅《论语》《心经》有真实样张，其余经 `AB.isSampleText(book)` 判定后显示「演示样张」提示；③ 所有 `localStorage` 读写统一走 `AB.lsGet/lsSet`（try/catch），否则 `file://` 直开或隐私模式下抛异常会让偏好整体失效。
- **多会话并行提交风险（2026-09-08 实测）**：别的用户会话会在本会话编辑中途执行 `git add -A && git commit`，把半成品改动与 `scripts/` 下的临时脚本一并入库。因此：临时脚本用完立即删除（不要留在会被 `-A` 扫到的目录）；每次动手/收尾先 `git status` + `git log -1` 确认 HEAD 与工作区真实状态。
- **原型样式结构（v1.3.4 起）**：`prototype/assets/prototype.css`（316 行）已删除，拆为 `prototype/assets/css/` 六文件并按序引入：`base` → `components` → `home` → `reader` → `pages` → `responsive`（`responsive` 必须最后加载以覆盖媒体查询）；`theme-color.css` 仍为三主题变量单独文件。11 个 HTML（prototype.html + pages/*.html + wireframes.html）均按 `./` 或 `../` 相对层级引入。**CSS 内相对资源路径已从 `./images/...` 改为 `../images/...`**，新增样式文件时注意目录层级。
- **原型审查坑（`prototype/`，v1.3.0 起已非运行站点）**：① 综合页容器 `#main-view`、独立页 `#page-body` 必须统一用 `getMain()` 取，否则独立页二次渲染拿到 `null` 崩溃；该辅助函数曾在 v1.2.10 误写成 `function getMain(){ return getMain(); }` 造成无限递归（v1.3.2 修复）；② `app-data.js` 的 38 位/6 关系人物派生为 v1.2.8–v1.2.10 期间演示数据，v1.3.0 已随 `data-generated.ts` 删除而失效，`prototype/` 现属遗留演示、不再驱动运行站点；③ 改 `prototype.*` 前务必先 `read_file` 确认当前内容，版本号以 `package.json` 为权威源（HEAD 长期高于会话假设值）。
- **Actions 版本基线（2026-09，v1.2.4）**：Node 24 运行时要求 `checkout@v7` / `setup-node@v7` / `upload-artifact@v7` / `upload-pages-artifact@v5` / `deploy-pages@v5`；旧版（v4/v3）会被强制以 Node 24 运行并产生 `Node.js 20 is deprecated` 告警。坑：`upload-pages-artifact` v4+ 默认不上传隐藏文件，需 `include-hidden-files: true` 才能带上 `.nojekyll`。
- **构建环境变量红线（v1.2.6 起）**：生产（EdgeOne / guji.ewuse.com）为**根路径**部署，构建环境**禁止**设置 `NEXT_PUBLIC_BASE_PATH`——该变量仅 GitHub Pages 子路径部署使用。误设会使产物内 CSS/JS/icon/站内链接全部带 `/ancient-book-lib` 前缀而 404（v1.2.6 前 `next.config.mjs` 在生产环境默认就带此前缀，已修）。注意 Next export 不会把页面输出到 `out/ancient-book-lib/`，因此页面 URL 仍 200、只有资源 404，极易误判。
