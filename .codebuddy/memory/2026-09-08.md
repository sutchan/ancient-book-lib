## 跟进（同日二次复现，根因修正为「仓库私有」）

- 用 node fetch 直测（PowerShell 的 `curl` 是 `Invoke-WebRequest` 别名，参数不兼容，勿用）：
  - `GET /repos/octocat/Hello-World` → 200（网络正常）
  - `GET /users/sutchan` → 200（用户存在）
  - `GET /repos/sutchan/ancient-book-lib` → **404**
  - `GET /repos/sutchan/ancient-book-lib/pages` → 404
- 结论：Actions 能跑说明仓库存在，`repos` API 匿名 404 ⇒ **仓库为私有**。免费计划不支持私有仓库 Pages，因此 Settings → Pages 无可选项，deploy-pages 持续 404。
- 解法优先级：① 转 Public（Settings → Danger Zone → Change visibility，符合开源定位）→ 再 Settings → Pages → Source = GitHub Actions；② 账号升级 Pro/Team（私有库 Pages 需付费）；③ 保持私有则换 Vercel / Cloudflare Pages / EdgeOne Pages，并弃用 Pages workflow。
- 私有 → Public 转换后遗留项提醒：仓库仍缺 LICENSE 文件。

## 线上重大故障排查与修复（v1.2.6）

- 现象：线上 https://guji.ewuse.com/ 首页 200，但 39 个内部引用中 **26 个 404**——`/_next/static/**`、`icon.png`、`apple-icon.png`、`/catalog/`、`/book-list/`、`/character/` 等全部带 `/ancient-book-lib/` 前缀。
- 根因：`next.config.mjs` 写 `basePath = env.NEXT_PUBLIC_BASE_PATH || (isProd ? "/ancient-book-lib" : "")`，生产构建默认加前缀；而生产部署在根路径。Next export **不会**把页面输出到 `out/ancient-book-lib/`，所以 `/catalog/` 仍 200，但页面内所有资源与链接 404 ⇒ 无样式、导航全挂。
- 修复：默认改为根路径（仅显式 env 启用），已用 file:// 动态 import 验证：默认 `{}`、设 env 时 `basePath=/ancient-book-lib`。
- 连带修复：`scripts/generate-sitemap.mjs` SITE_URL 默认改 `https://guji.ewuse.com`、BASE_PATH 默认 ""；`public/robots.txt` Sitemap 行去掉 github.io；`app/layout.tsx` 补 `alternates.canonical` 与 `openGraph.url`（线上原缺失）。
- 未验证项：本地 `next build` 因环境 safe-delete shim（删除 .next 时 win32-x64.exe ETIMEDOUT）无法跑通，非代码问题；需在 CI 或 EdgeOne 侧确认。
- 部署要点（已写入部署规范）：EdgeOne 构建环境**不得**设置 `NEXT_PUBLIC_BASE_PATH`。

## 品牌资料套件（v1.2.2）

- 需求：把 `public/images/logo.png` 转成应用各处可用的品牌资料文件。
- 关键发现：该文件**扩展名是 .png 但实际是 JPEG**（签名 ffd8ff，2048×2048，706KB）；内容布局为「左侧朱红方印 + 右侧黑色「古籍通 / AncientBook」」横版，外接框 x=392 y=784 w=1292 h=480，**比例 2.692:1**，四周留白 40%；背景是**米色纸底（亮度 240–252，非纯白）**，印章内部白色线条亮度与纸底接近。
- 工具链：无 sharp/pngjs/PIL，最终用 **Windows .NET System.Drawing（GDI+）** 写 PowerShell 脚本生成，零新增依赖。脚本须 **UTF-8 BOM**（PS 5.1 否则中文乱码），并在入口设 `[Console]::OutputEncoding = UTF8`。
- 抠底算法：亮度阈值（Solid 232 / Clear 242）+ **印章保护矩形**（内缩 7%），否则印章内白线被误抠；对白底做反预乘消除白边。先按亮度抠会全图变半透明雾（背景亮度 251 > 阈值 246）。
- 产物：`public/brand/`（logo-full 1024/512/256 + light 反白版、logo-mark 512→16、solid-180、maskable-512、og-image 1200×630、brand-tokens.json、logo-source.jpg）；接入位 `app/icon.png`(64)、`app/apple-icon.png`(180)、`app/opengraph-image.png`、根 `favicon.ico`(16/32/48/64 内嵌 PNG)、`apple-touch-icon.png`、`site.webmanifest`。
- 主色采样为 **#A93320**（印章朱红），纸色 #F7F3EA；UI 主题色仍是 `--color-primary:#8C3130`，两者不互相覆盖。
- 代码接入：`app/layout.tsx` 加 metadataBase(https://guji.ewuse.com)/manifest/appleWebApp/openGraph/twitter + `viewport.themeColor`；`components/Navbar.tsx` 深色主题自动切 `logo-full-light-512.png`。
- 构建验证：`next build` 生成 117 页，`/icon.png`、`/apple-icon.png`、`/opengraph-image.png` 路由均已产出；`tsc --noEmit` 通过。
- 坑：IDE 的 safe-delete shim 会让 `fs.rmSync('.next')` 与 next 自身清缓存失败（trash 报错），绕法是用 node 删或重跑 build；`execute_command` 偶尔被判"耗时"直接 skip，重试一次通常就过。
