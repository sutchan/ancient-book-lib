## GitHub Pages 部署 404 排障 + 流水线加固（v1.0.4）

- 现象：`actions/deploy-pages@v4` 报 `HttpError: Not Found / Failed to create deployment (status: 404)`。
- 根因（已用 `GET https://api.github.com/repos/sutchan/ancient-book-lib/pages` 验证返回 404）：仓库 **Pages 站点未启用**，需在 Settings → Pages → Source 选 **GitHub Actions**。此 404 与代码/产物/权限无关。
- 代码侧改动（v1.0.4）：
  - `.github/workflows/deploy.yml`：PR 不再上传产物（`if: github.event_name != 'pull_request'`）；`concurrency.cancel-in-progress: false`（防部署被取消）。
  - 新增 `public/.nojekyll`（防 Jekyll 忽略 `_next/`）。
  - `docs/06-部署与迭代/项目部署上线规范.md` 新增 §5 GitHub Pages CI/CD 章节（启用步骤、路径约束、告警说明），文档版本 V1.0→V1.1。
  - 版本 1.0.3 → 1.0.4（package.json / README 展示 / CHANGELOG 新小节 + 比较链接）。
- 重要约束（待用户决策）：Pages 默认地址带 `/ancient-book-lib/` 子路径，而全站链接与资源为根路径（约 27 处硬编码 `/`、Navbar logo `/images/logo.png`），子路径下会 404。**推荐 Pages 绑定自定义域名走根路径**（零代码改动）；改用 basePath 需批量改造链接，不推荐。
- 无害提示：Node 20 弃用告警（`DEP0040 punycode`）来自 action 运行时，无需处理。

## 跟进（同日二次复现，根因修正为「仓库私有」）

- 用 node fetch 直测（PowerShell 的 `curl` 是 `Invoke-WebRequest` 别名，参数不兼容，勿用）：
  - `GET /repos/octocat/Hello-World` → 200（网络正常）
  - `GET /users/sutchan` → 200（用户存在）
  - `GET /repos/sutchan/ancient-book-lib` → **404**
  - `GET /repos/sutchan/ancient-book-lib/pages` → 404
- 结论：Actions 能跑说明仓库存在，`repos` API 匿名 404 ⇒ **仓库为私有**。免费计划不支持私有仓库 Pages，因此 Settings → Pages 无可选项，deploy-pages 持续 404。
- 解法优先级：① 转 Public（Settings → Danger Zone → Change visibility，符合开源定位）→ 再 Settings → Pages → Source = GitHub Actions；② 账号升级 Pro/Team（私有库 Pages 需付费）；③ 保持私有则换 Vercel / Cloudflare Pages / EdgeOne Pages，并弃用 Pages workflow。
- 私有 → Public 转换后遗留项提醒：仓库仍缺 LICENSE 文件。
