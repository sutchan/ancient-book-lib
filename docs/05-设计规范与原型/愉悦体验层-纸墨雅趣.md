# 愉悦体验层 · 纸墨雅趣

> 以「愉悦体验设计师」视角为古籍通注入的微交互体系。设计原则：**克制而有文气**，拒绝廉价花哨；用古籍意象（墨、朱砂、纸、卷）承载现代微交互，让功能完备的产品更有「惊艳感」与情感连接。

## 1. 设计理念

| 维度 | 取向 |
| --- | --- |
| 基调 | 墨色沉静、朱砂点睛，动效如宣纸晕染，不抢阅读主线 |
| 强度 | 微交互为主（hover / 滚动 / 空态），彩蛋为辅（探索奖励） |
| 范围 | 仅增强、不阻碍任务完成；动效开销极低，纯 CSS / 原生 JS，零第三方依赖 |
| 红线 | 全部动效尊重系统「减弱动态效果」偏好；不干扰读屏与键盘操作 |

## 3. 原型 ↔ 代码 同步契约

愉悦体验层**刻意双份实现**：原型（`prototype/`）是面向投资人 / 评审的高保真演示，正式站（`app/`）是真实运行站点。二者必须保持视觉与行为一致。

**强一致清单（改一处必同步另一处）**

- CSS 愉悦层：`prototype/assets/css/components.css` 末段「愉悦体验层（Delight Layer）」⇔ `app/globals.css` 末段。两份开头均互注「与 … 保持同步」，禁止只改一边。
- 检索空态：原型 `view-search.js` 的 `.empty-state` / `.empty-suggest` 文案与可点建议词，必须与 `SearchClient.tsx` 一致。
- 卷首进度 / 页脚彩蛋的**触发条件、动画参数、无障碍行为**必须一致（reduced-motion 下仅 toast，不飞字）。

**实现差异（允许，但需显式注释）**

- 原型为经典脚本（`window.AB` 全局命名空间、`file://` 直开），正式站为 React 客户端组件；行为相同、写法不同。
- 原型建议词点击走 `AB.state.searchKeyword` + `renderSearch()`；正式站走 Next `Link` 跳转 `/search?q=…&mode=full`。

## 4. 无障碍红线（强制）

- 所有 `@keyframes` 动画与 hover 过渡必须包裹在 `@media (prefers-reduced-motion: no-preference)` 内；`reduce` 用户下动效直接省略或瞬时跳变（进度条仍可见，只是无过渡）。
- 卷首进度条 `pointer-events:none` 且 `aria-hidden`；页脚彩蛋 toast 用 `role="status"`，不抢焦点、不阻断读屏。
- 朱砂线 / 朱笔标记等纯装饰伪元素 `pointer-events:none`，不覆盖可点击区域。
- 颜色仅用主题变量（`--color-primary` 等），深色 / 护眼主题自动适配；唯水光高光用 `rgba(255,255,255,0.35)`，三主题均可读。

## 5. 扩展指引（新增触点）

1. 先在 `prototype/assets/css/components.css` 愉悦层段加样式 + 在 `app/globals.css` 同段加**完全一致**的一份（互注同步）。
2. 行为类触点（进度 / 彩蛋 / 重抽）在原型 `core.js` / `view-*.js` 加 `AB.xxx` 函数，在 `boot.js` 挂载；正式站加对应 `components/*.tsx` 并在父组件渲染。
3. 文案改动同步 `SearchClient.tsx` 与 `view-search.js`。
4. 自测：`node --check` 原型 JS、`tsc --noEmit` 正式站、并在系统开启「减弱动态效果」下回归一遍。
