## 一、核心问题诊断（按严重度排序）

### 1.1 页面完整性缺口（🔴 高优先级）

**现状**：`docs/05-Figma原型建模清单` 承诺全站 8 个核心页面，但 `pages/` 目录实际仅有 `index.html` 1 个独立页面，其余 7 个（category、book-list、read、search、character、relation、help）缺失，仅存在于 prototype.html 的 JS 内联渲染中。

**影响**：无法独立演示单页面细节、无法按页面评审、无法直接作为前端开发逐页还原的参照。

**改进方案**：
1. 补齐 7 个独立页面文件：`category.html`、`book-list.html`、`read.html`、`search.html`、`character.html`、`relation.html`、`help.html`
2. 每个独立页面完整实现：面包屑、标题区、内容区、页脚四段结构
3. 独立页面与 prototype.html 内联视图共用同一套 assets 样式与交互脚本，保证视觉零偏差

### 1.2 数据未打通（🔴 高优先级）

**现状**：`data/` 下已有 `book-data.json`、`search-data.json`、`character-data.json` 三份模拟数据，但页面渲染全部使用 JS 内联硬编码数据，JSON 文件形同虚设。

**影响**：换数据必须改代码，无法模拟真实数据规模，评审时无法验证数据驱动能力。

**改进方案**：
1. 页面脚本改为 `fetch('./data/book-data.json')` 动态加载渲染
2. 扩充模拟数据规模：十大藏库各 5-10 本书、每书 10-20 章节、人物 20+、关系 30+ 条，模拟真实数据体量
3. 增加数据加载失败兜底（展示空状态 + 重试按钮）

### 1.3 繁简切换未落地（🔴 高优先级）

**现状**：导航栏「繁简」按钮仅切换按钮文字（"繁体"↔"简体"），正文内容无任何转换，演示效果失真。

**影响**：繁简双语是产品核心差异化能力，原型无法演示 = 评审看不到核心卖点。

**改进方案**：
1. 内置轻量繁简对照映射表（覆盖常用字 + 古籍常见字，如「学→學」「习→習」「说→說」）
2. 切换时遍历正文文本节点，按映射表实时转换
3. 保留「繁体原版 100% 展示」与「简体对照」两种模式的状态记忆

### 1.4 检索交互未闭环（🟠 中优先级）

**现状**：搜索框无实际检索逻辑，输入关键词点击搜索无响应；无检索历史、无空状态、无加载态。

**改进方案**：
1. 基于 `data/book-data.json` 实现前端内存关键词过滤检索
2. 命中结果高亮 `<mark>`、展示路径、章节、上下文片段
3. 补充三态演示：加载中（骨架屏）→ 有结果 / 无结果（空状态）
4. 检索词本地缓存，支持检索历史点击回填

### 1.5 移动端体验缺失（🟠 中优先级）

**现状**：CSS 定义了 `.nav-hamburger` 与媒体查询折叠规则，但 JS 未绑定汉堡按钮点击事件，移动端菜单不可用；阅读页无移动端优化。

**改进方案**：
1. 实现汉堡菜单开合：点击展开/收起导航菜单，带过渡动画
2. 移动端阅读页：正文字号自适应、全屏沉浸、按钮触控区域 ≥44px
3. 移动端预览说明：原型头部增加设备切换（桌面/平板/手机）预览条

### 1.6 动效体系不足（🟠 中优先级）

**现状**：仅卡片 hover 微效，无页面切换过渡、无加载动效、无滚动预加载动效，与「高保真带动效」定位不符。

**改进方案**：
1. 页面切换：hash 路由切换时内容区淡入 + 轻微上移动画（200-300ms）
2. 卡片入场：滚动进入视口时逐卡淡入（IntersectionObserver）
3. 章节分片加载模拟：阅读页滚动到底部显示「加载下一片」占位 + 骨架屏
4. 弹窗/划词释义：淡入缩放动效，不遮挡正文

### 1.7 阅读页功能不完整（🟡 中优先级）

**现状**：阅读页仅有正文 + 上下章按钮，缺字号调节、行距调节、进度记忆、划词释义、章节分页。

**改进方案**：
1. 阅读控制面板：字号（14/16/18/20px）、行距（1.6/1.8/2.0）滑块调节
2. 阅读进度：当前章节进度百分比 + 本地缓存记忆（localStorage）
3. 划词交互：选中文本弹出「释义/检索」轻量浮层
4. 生僻字点击弹窗释义演示（内置 2-3 个字词释义数据）

### 1.8 字体系统未落地（🟡 低优先级）

**现状**：CSS 声明了 `Noto Serif SC / 思源宋体`，但未实际加载字体资源，实际渲染为系统默认字体，视觉质感与规范不符。

**改进方案**：
1. 引入 Google Fonts / 本地字体文件加载 `Noto Serif SC`
2. 正文强制衬线字体渲染，验证古籍阅读质感
3. 设置 font-display: swap 避免阻塞首屏

### 1.9 组件库状态演示不完整（🟡 低优先级）

**现状**：wireframes.html 有组件展示，但缺 hover/active/disabled/focus 各状态演示、三套主题切换演示、组件尺寸规范标注。

**改进方案**：
1. 每个组件补全四态展示（default/hover/active/disabled）
2. 页面顶部加主题切换按钮，演示三套主题下组件表现
3. 标注关键尺寸（圆角 6px、间距 8/16/24px、字号层级）
4. 增加「组件使用规则速查表」

### 1.10 无障碍与语义化缺失（🟡 低优先级）

**现状**：无 aria 标签、无键盘导航支持、图标按钮无文字说明。

**改进方案**：
1. 导航、按钮补充 `aria-label`、`role` 语义
2. 支持键盘 Tab 导航 + Enter 触发
3. 图片/装饰元素补充 `alt=""` 或 aria-hidden

## 三、改进后验收标准

1. **页面完整**：`pages/` 下 8 个独立页面全部存在且可独立打开
2. **数据驱动**：三个页面类型（馆藏/检索/人物）均从 JSON 动态渲染
3. **繁简可演示**：点击繁简按钮，正文真实转换（简体↔繁体）
4. **检索可用**：输入关键词可过滤出结果、高亮命中、空状态正确
5. **三端适配**：375/768/1200px 三档预览布局正确、菜单可用
6. **动效达标**：页面切换、卡片入场、分片加载均有过渡动画
7. **阅读完整**：字号/行距可调、进度记忆、划词释义可用
8. **组件规范**：wireframes 四态齐全、主题演示可用
9. **字体还原**：正文渲染为衬线古籍字体
10. **无障碍**：主要交互元素具备 aria 标签与键盘可达性
