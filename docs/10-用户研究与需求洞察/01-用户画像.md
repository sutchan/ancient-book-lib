# 用户画像（Personas）

> **说明**：本画像基于「古籍通 AncientBook」产品定位（开源、全量 15,694 部古籍在线、纯静态无数据库、繁简对照、划词溯源、远程阅读）推导得出，用于指导产品决策。尚未经过真实用户调研验证，后续应通过用户访谈和可用性测试修正。

---

## 画像一：文史研究者（核心用户）

| 维度 | 描述 |
|------|------|
| **身份** | 高校文史专业研究生、青年教师、独立研究者 |
| **年龄** | 22–45 岁 |
| **技术能力** | 中高级，能使用命令行、GitHub、文献管理工具 |
| **使用频率** | 高频，每周 3–5 次，每次 30–120 分钟 |
| **核心场景** | 查阅某部古籍的特定章节、跨书检索人名/地名/典故、比对不同版本文本 |
| **核心需求** | ① 全文检索精准（支持繁简混合查询）② 划词溯源（选中文字立即检索其他古籍中的出处）③ 下载原文用于离线研究 ④ 章节目录清晰可跳转 |
| **痛点** | ① 商业古籍库（如中国哲学书电子化计划）部分内容需付费 ② 古籍文本检索结果常因繁简差异漏检 ③ 找到出处后无法快速跳转原文 ④ 大文件加载慢 |
| **对本项目的价值感知** | 全量免费 + 划词溯源 + 繁简对照 = 研究效率提升 |
| **付费意愿** | 低（学术预算有限，倾向免费开源工具），但愿意捐赠/贡献代码 |
| **流失风险** | 若检索精度不足或数据不全，会转回商业数据库 |

## 画像二：传统文化爱好者（重要用户）

| 维度 | 描述 |
|------|------|
| **身份** | 对国学、历史、古典文学感兴趣的普通读者 |
| **年龄** | 25–55 岁 |
| **技术能力** | 初级到中级，习惯使用手机/平板阅读 |
| **使用频率** | 中频，每周 1–3 次，每次 15–60 分钟 |
| **核心场景** | 闲暇时阅读经典古籍（论语、道德经、史记等）、了解古代文化、摘抄名句 |
| **核心需求** | ① 界面简洁无广告 ② 简体对照（繁体原文阅读障碍）③ 字号/行距可调 ④ 阅读进度自动保存 ⑤ 推荐入门书籍 |
| **痛点** | ① 繁体原文看不懂 ② 古籍排版不适合手机阅读 ③ 不知道从哪本开始读 ④ 广告弹窗干扰阅读 |
| **对本项目的价值感知** | 纯净无广告 + 简体对照 + 阅读体验好 = 沉浸式阅读 |
| **付费意愿** | 低到中，可能为去除广告或更好体验付费，但本项目承诺永久免费 |
| **流失风险** | 若阅读体验不如微信读书/得到等平台，会流失 |

## 画像三：学生用户（增长用户）

| 维度 | 描述 |
|------|------|
| **身份** | 中学生、大学生（文史相关专业或通识课需求） |
| **年龄** | 15–22 岁 |
| **技术能力** | 中级，数字原住民，习惯快速搜索和碎片化阅读 |
| **使用频率** | 低频到中频，考试/写论文时集中使用，平时偶尔浏览 |
| **核心场景** | 写课程论文查找原文引用、完成语文/历史作业、课外阅读经典 |
| **核心需求** | ① 搜索快速精准 ② 能直接定位到具体段落 ③ 引用方便（复制原文）④ 移动端适配好 |
| **痛点** | ① 不知道某句话出自哪本书 ② 找到书后翻不到具体章节 ③ 复制时格式混乱 ④ 学校网络限制 |
| **对本项目的价值感知** | 免费 + 搜索快 + 可直接引用 = 写论文好帮手 |
| **付费意愿** | 极低（学生无收入） |
| **流失风险** | 若百度学术/知网等能满足需求，可能不使用本项目；但本项目的古籍全文检索是差异化优势 |

## 画像四：开发者/数据使用者（生态用户）

| 维度 | 描述 |
|------|------|
| **身份** | 软件开发者、NLP 研究者、数据科学家、数字人文研究者 |
| **年龄** | 22–40 岁 |
| **技术能力** | 高级，能编写脚本、调用 API、处理大规模文本数据 |
| **使用频率** | 低频但高价值，项目需要时集中使用 |
| **核心场景** | 批量下载古籍文本用于 NLP 训练/分析、构建古籍知识图谱、二次开发古籍应用 |
| **核心需求** | ① 数据可批量获取（GitHub raw URL 直链）② 数据格式规范（UTF-8 TXT）③ 元数据完整（书名、分类、大小）④ 开源协议清晰 ⑤ 索引可下载 |
| **痛点** | ① 商业古籍库 API 收费或限制调用 ② 数据格式不统一 ③ 缺少元数据 ④ 大规模下载被封 IP |
| **对本项目的价值感知** | 全量开源 + raw URL 直链 + 元数据索引 = 数据获取零门槛 |
| **付费意愿** | 低（倾向开源免费），但可能贡献代码/数据/文档 |
| **流失风险** | 若上游数据更新不及时或索引不完整，可能自行爬取其他数据源 |

## 用户画像优先级矩阵

| 画像 | 价值 | 获取成本 | 优先级 | 策略 |
|------|------|----------|--------|------|
| 文史研究者 | 高（核心口碑传播者） | 中 | **P0** | 优先满足检索精度、划词溯源、下载需求 |
| 传统文化爱好者 | 中高（用户量最大） | 低 | **P0** | 优先满足阅读体验、简体对照、进度保存 |
| 学生用户 | 中（增长潜力大） | 低 | **P1** | 优化搜索体验、引用便捷性、移动端 |
| 开发者/数据使用者 | 中（生态建设） | 中 | **P1** | 保持数据开放、完善索引和文档 |

---

## 共性需求（所有画像）

1. **数据真实可靠**：原文必须忠实于上游数据源，不做篡改或删减
2. **无广告无干扰**：阅读体验纯净，符合项目承诺
3. **加载速度可接受**：尤其是大文件（>5MB）需要进度提示和缓存
4. **移动端可用**：越来越多用户通过手机访问
5. **隐私保护**：所有用户配置本地存储，不上传个人数据
