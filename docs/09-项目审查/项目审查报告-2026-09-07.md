## 1. 总体结论

项目工程化底座**健康**：纯静态架构严守（无数据库、无动态接口、65 页全 SSG）、CI/CD＋测试＋GA 已闭环、单一数据源与索引脚本可扩展、文档体系完备。但 **V1.0 上线验收存在 3 项阻塞、6 项重要缺口**，主要集中在：① 真实 5GB 数据未接入（当前为 45 部演示数据）；② 下载模块整体缺失；③ 若干 PRD 承诺功能（高级检索、进度缓存、书籍详情路由）未实现或仅占位。

**结论：当前状态为「可演示的内核 Demo」，尚未达到 PRD 所定义的「可直接上线」验收标准。** 架构方向正确、工程健康，缺的是上线必需的数据接入与功能闭环。

## 2. 阻塞项（不解决不可宣称上线）

### B1. 真实 5GB 古籍数据未接入（核心承诺未兑现）
- **证据**：`lib/data-generated.ts` 为 45 部演示数据；`scripts/build-index.mjs --fulltext --data-dir` 已具备真实 TXT 接入能力，但仓库未配置 Git LFS、无真实数据分片、`public/index/` 为演示索引（185 词条）。
- **影响**：PRD §1.5/§3「5GB 十大藏库全文在线、Range 分片懒加载、毫秒级全文检索」均停留在降级演示路径；上线后无真实全文可读可检。
- **建议动作**：① 仓库启用 Git LFS，按 `书名/章节.txt` 目录结构提交真实 TXT 分片（或外链 RAW 域名白名单）；② 跑通 `build-index:full --data-dir data` 生成生产索引；③ 用真实文本做分片加载与检索压测。
- **验收方式**：检索任意真书正文命中并返回章节片段；阅读页按字节 Range 拉取真实章节内容。

### B2. 合规下载模块整体缺失
- **证据**：`app/`、`components/` 全库检索 `download|下载|Blob` 命中 0；PRD §4.7、任务清单 3.5 要求的单章节/单本/单馆藏三级下载、解压密码与备用网盘公示、下载免责挂载均无。
- **影响**：PRD「浏览、检索、双语阅读、分片加载、考据、**下载**、合规公示全闭环」验收标准中的下载闭环断裂；目标用户「文本复用」核心诉求无法满足。
- **建议动作**：V1.0 实现最小下载闭环：单章下载（Blob 生成 TXT，繁简按当前模式）、整本/馆藏下载跳转网盘公示区；所有下载入口挂载免责声明；页脚补齐真实解压密码/网盘链接（当前为占位 `pan.example.com`）。
- **验收方式**：任一章节点击下载得到可打开 TXT；下载入口可见免责与网盘公示。

### B3. 繁简映射体系远未达「古籍学术级保真」
- **证据**：`lib/t2s.ts` 现有 376 字；PRD §3.1/§4.4 要求「古字、异体字、避讳字、官职、年号、专有名词完整映射库」。用真实古籍文本抽样（每章 2–4KB 约 1000+ 字）预计仍有数百字未覆盖。
- **影响**：简体对照模式在真实文本上会出现大量繁体残留或错转，直接击穿「学术级保真」核心差异化；也是索引归一化的前置缺陷（词条分裂）。
- **建议动作**：构建期从真实语料自动抽取未覆盖字生成映射增量表（脚本已具备扫描能力，扩展 `expand-t2s` 接入真实语料）；补专有名词表（官职/年号/地名）走白名单规则而非单字映射。
- **验收方式**：随机抽取 5 部真实古籍各 1 章，简体转换后繁体残留率 <0.5% 且无错转案例。

## 3. 重要项（显著影响价值与验收）

### I1. 阅读进度缓存未实现（仅有文案）
- **证据**：`ReaderClient.tsx` 仅缓存繁简偏好；「阅读进度已自动保存」为静态文案，`chapterIdx` 未持久化。
- **建议**：`localStorage` 保存 `{书ID: chapterIdx}`，进入页面时恢复；同步实现「已读片段缓存」（任务清单 3.1）。

### I2. 高级学术检索未实现
- **证据**：`SearchClient.tsx` 仅标题/全文双模式＋每页条数；无朝代/地域/人物/馆藏/文体多维筛选、无阅读页划词一键溯源（PRD §4.3.2、任务 3.3）。
- **建议**：V1.0 先落地馆藏＋朝代两个筛选维度＋阅读页划词跳检索（getSelection 传递关键词）；人物关联检索并入人物页。

### I3. 首页搜索框无实际功能
- **证据**：`app/page.tsx` 搜索框仅 `<input name="q">`＋跳转按钮，不传关键词、无双模式切换（PRD §4.1「全局置顶一体化搜索框，双模式」）。
- **建议**：表单提交带 `?q=` 至 `/search`，`SearchClient` 读取 URL 参数初始化；双模式开关可放检索页。

### I4. 路由未对齐 PRD：缺书籍详情页
- **证据**：PRD §6 规定 `/book/[id]` 书籍详情＋章节目录页；当前为 `/book-list`（列表）＋`/read/[书名]`（直接读），无「书籍详情＋三级目录」页面。
- **建议**：新增 `/book/[id]` 详情页（书目信息＋章节树＋下载入口），`/read` 改为按章节定位 `/read/[bookId]/[chapterIdx]`（或保留现有并新增详情页承接目录职责）。

### I5. CBDB 人物考据为演示数据且未达承诺深度
- **证据**：21 位演示人物；「文献自动关联聚合（一键展示该人物全馆藏记载）」未实现（仅有静态 books 字段）；重名人物区分无 UI（数据层已有 ID 但页面未用）。
- **建议**：V1.0 完成「人物→典籍记载」聚合展示与重名筛选交互（数据层结构已就绪）；真实 CBDB 子集随数据接入导入。

### I6. 对外口径与真实数据不一致
- **证据**：README/统计页/页脚多处表述「45+ 部」「十大藏库全文在线」，而真实数据未接入；统计页虽标注「演示」，但站点整体未统一「演示版」身份。
- **建议**：数据接入前全站统一标注「演示预览版」；接入后按真实数字刷新统计与文案，避免误导与合规风险。

- 文档体系：PRD、任务清单、架构、合规、部署规范齐全，隐私表述（GA4）已全站口径统一。
- 原型先行：prototype 高保真原型与 Next.js 实现同源，评审建议（检索模式、影像对照等）已回灌实现。
