## 1. 项目综述

### 1.1 项目背景

本项目依托殆知阁开源十大藏库资源，整合总计5GB高纯无噪纯TXT古籍文本，是国内公开可获取的完整性、保真度、权威性顶尖的开源古籍文库。原始资源托管于GitHub，仅为静态文本文件，存在检索低效、超大文件无法完整加载、无章节结构化拆分、无繁简保真对照、无学术考据联动、下载体系混乱、移动端体验缺失等原生短板，无法直接普惠使用与学术研究。

市面现有古籍平台普遍存在能力割裂问题：大众阅读平台仅有原文浏览、无学术考据与文本深加工能力；人文学术数据库（CBDB等）仅有人物史料数据、无完整古籍原文阅读与典籍溯源能力，二者无法打通，形成「阅读无考据、考据无原文」的行业痛点。

本项目基于 Next.js 14 全静态 SSG 架构重构，**永久舍弃传统数据库存储方案**，采用「本地离线索引预构建 + 前端内存检索 + 远程分片懒加载」创新架构，彻底解决超大文本入库膨胀、部署崩溃、检索超时等问题。在**完全保留古籍原文保真、不膨胀资源体积、零运维成本**的前提下，实现「大众普惠阅读 + 专业学术考据 + 古籍文本深度挖掘」三位一体的完整产品闭环。

### 1.3 产品定位（双轨精准定位）

**基础普惠定位**：零广告、零注册、零付费、不收集个人隐私的纯公益开源古籍工具（仅匿名访问统计，GA4），面向学生、国学爱好者、传统文化学习者，提供结构化浏览、毫秒级检索、保真双语阅读、规范化资源下载等基础核心能力，实现古籍资源全民普惠。

**专业学术定位**：轻量化人文考据研究工具，对标哈佛CBDB、中研院史学数据库学术能力，打通古籍全文资源与历代人物、官职宦历、社会关系、朝代史料、典章制度的联动溯源，服务文史教学、学术研究、古籍校勘、国风内容创作。

**核心差异化优势（行业壁垒）**：

- 独创无数据库超大文本解决方案，5GB资源零体积膨胀、零部署风险、零运维成本，碾压传统数据库古籍架构

- 线上生产环境**不存储、不入库、不复制、不篡改原始大文件**，100%保留原版古籍文本保真度
- 所有原文在线调用统一采用「离线索引字节定位 + 远程Range分片懒加载」模式，规避GitHub限流、超时、截断问题
- 馆藏分类全覆盖：佛藏、儒藏、医藏、史藏、子藏、易藏、艺藏、诗藏、道藏、集藏十大正统古籍文库

- 行业普遍空白：现有平台均未挖掘古籍深层价值，仅停留在「阅读检索」浅层能力，浪费海量古籍语料与文史数据资源

## 3. 整体产品架构（终审技术定稿·不可变更）

**架构模式：纯静态无数据库架构（古籍数字化平台行业最优落地方案）**

整体链路：GitHub原始开源资源 → 本地离线全量预处理 → 静态分级索引池生成 → Next.js SSG全静态预构建 → 前端内存检索计算 + 远程分片懒加载 → 全终端极速访问

### 3.1 离线预处理固定流程（迭代强制规范）

- 本地完整克隆上游5GB古籍资源，禁止线上批量拉取超大文件，规避网络与限流风险
- 智能语义分块：按古文段落、章节语义拆分，单块2–4KB，兼顾检索精度与加载性能，不破坏原文语义结构
- 构建馆藏分级静态倒排索引，仅存储词条、权重、位置、字节偏移、文件路径，**不存储任何原文**，极致控容
- 生成古籍专属繁简双向映射库，固化古字、异体字、避讳字、官职、年号、专有名词转换规则，实现学术级保真
- 输出轻量化静态索引池（总体300–700MB），提交代码仓库，线上永久静态复用

### 3.2 线上运行核心机制（稳定保障）

- 全站SSG静态预渲染，页面零动态服务端渲染、零接口依赖，首屏秒开、无构建超时、无白屏卡顿
- 全文检索完全在前端内存执行，毫秒级响应，无服务端计算压力、无查询超时风险
- 超大文本采用HTTP Range分片精准请求，仅加载当前阅读章节片段，彻底解决大文件加载问题
- 前端本地缓存用户偏好、已读片段、检索记录，二次访问极速加载，大幅提升复用体验

### 3.3 架构核心优势（验收硬性指标）

- 零体积膨胀：原始5GB古籍资源完全保真，索引体积可控，无数据库冗余膨胀
- 零运维成本：纯静态文件形态，Vercel/私有服务器一键部署，无需运维、无需备份、无需迁移
- 零崩溃风险：彻底规避数据库OOM、查询超时、带宽超限、连接异常等各类线上故障
- 超高性能：检索响应20–80ms，性能碾压所有传统数据库检索古籍平台

## 4. 核心功能详细需求（V1.0 上线完整版）

### 4.1 首页模块

- 全局固定导航栏：首页、十大藏库、考据工具、使用须知、繁简切换按钮
- 全局置顶一体化搜索框，支持标题检索、全文检索双模式切换
- 馆藏可视化卡片入口，十大藏库分类展示，SSG静态预渲染秒开
- 学术工具快捷入口：人物考据、社会关系溯源直达页面
- 底部合规公示区：统一解压密码、备用网盘链接、开源协议、数据来源、免责声明、非商用规范

### 4.2 三级结构化分类浏览模块

解决原始文件无目录、整本体积过大、无法定点阅读、层级混乱的核心问题

- 一级目录：十大馆藏分类总览
- 二级目录：单本古籍书目列表
- 三级目录：章节、卷次、篇目精细化拆分列表
- 大文件分页懒加载、层级回溯定位、快速返回上级目录，浏览逻辑闭环

### 4.3 双模式极速检索模块（无数据库核心能力）

#### 4.3.1 基础检索

- 标题精准检索：精准匹配书名、卷名、篇目名，优先级最高
- 全文模糊检索：全库文本关键词匹配，自动高亮命中片段、定位上下文

#### 4.3.2 高级学术检索

- 多维度组合筛选：朝代、地域、人物、馆藏类别、文体类型
- 人物关联检索：通过姓名、字号、官职溯源匹配对应古籍记载篇目
- 阅读页划词检索：选中文本一键全局溯源检索，实现边读边考据

#### 4.3.3 检索权重排序规则（永久固化）

标题完全匹配 > 章节名完全匹配 > 段落开头精准匹配 > 正文高词频匹配 > 普通正文匹配

### 4.4 古籍级繁简双语保真阅读（平台核心差异化特色）

摒弃市面通用网页简易转换库，采用**离线预构建古籍专属繁简映射体系**，彻底解决古字、异体字、避讳字、专有名词错转、丢失、失真问题，达到学术考据级保真标准

- 繁体原版模式：100%还原GitHub原始古籍文本，零修改、零转换、零删减，满足学术校勘、考据保真需求
- 简体对照模式：官职、年号、古地名、专有名词精准适配，无语义丢失、无字词错乱
- 全站统一切换：目录、标题、正文、注解、检索结果全域双语同步生效
- 用户偏好本地永久缓存，自动记忆用户常用阅读模式

#### 4.4.1 上线标配阅读增强功能

- 日间/护眼/深色三套专业阅读主题，适配全天候阅读场景
- 字体大小、行间距自定义调节，适配手机、平板、桌面多终端
- 阅读进度自动缓存，退出重进精准定位上次阅读位置
- 章节分页展示、上下章一键切换，阅读体验连贯流畅
- 生僻字弹窗轻量化释义，不遮挡原文、不干扰阅读节奏

### 4.5 超大文本分片懒加载机制（线上稳定核心保障）

彻底解决GitHub超大TXT单文件数百MB加载超时、内容截断、IP限流、内存溢出等致命问题

- 离线索引预存每段文本的GitHub Raw原始字节偏移量与片段范围
- 在线阅读仅按需请求当前章节片段，绝不加载整本超大文件
- 基于HTTP Range协议精准分片请求，规避GitHub高频访问限流策略
- 前端本地缓存已读片段，重复访问零加载延迟、零重复请求

### 4.6 CBDB人文考据学术模块（平台核心学术壁垒）

基于纯静态结构化数据实现，无任何数据库支撑，对标专业史学数据库学术能力，打通古籍原文与人物史料的联动闭环

- 完整人物档案：姓名、字号、别称、朝代、生卒、籍贯、宦历官职、生平履历
- 文献自动关联：一键聚合展示该人物在全馆藏古籍中的所有篇目、诗文、传记记载
- 多元社会关系溯源：亲属谱系、师生、同僚、交游、上下级等多维关系梳理
- 双人关系查询：支持任意两位历史人物关联溯源，展示关联史料与出处
- 重名人物精准区分：唯一人物ID+朝代+籍贯+官职多维度过滤，解决历史人物重名混淆痛点
- 学术数据溯源标注：数据源为哈佛大学CBDB、中研院史语所、北大公开学术数据集，来源权威、可追溯、可考据

### 4.7 资源下载模块（合规完善版）

- 三级下载粒度：单章节精准下载、单本古籍整本下载、单馆藏批量下载
- 全站固定公示统一解压密码、备用百度网盘链接+提取码，解决资源失效问题
- 轻量化友好提示，规避高频批量下载导致的IP限流
- 所有下载入口附带开源协议、非商用免责声明，合规闭环

### 4.8 帮助、合规与共建模块（上线备案必备）

- 完整功能教程：检索、双语切换、考据工具、分片阅读全流程操作指南
- 开源共建说明：文本校对、古字纠错、索引优化、功能迭代志愿者招募规则
- 用户反馈渠道公示，建立常态化问题收集机制
- 完整开源声明、资源数据来源、非商用规范、法律免责条款，满足网站备案与线上合规要求

### 7.2 体验规范

### 7.3 兼容性规范

- 全终端响应式适配：手机、平板、桌面端完美适配

### 7.4 开源与合规规范（备案终审闭环）

- 平台永久定位：公益免费、开源共享、非商用传统文化传播工具
- 古籍资源严格遵循上游开源协议，禁止二次售卖、商用篡改、盈利复用
- 学术人物数据遵循CBDB公开学术开源规范，仅用于学术研究与文化传播
- 全站完整公示免责声明、开源协议、数据来源，规避版权与法律风险

## 9. 项目硬性约束（永久不可变更规则）

1. **永久禁用数据库**：项目全程维持纯静态文件架构，杜绝文本体积膨胀、部署故障与运维成本
2. **古籍原文永久保真**：GitHub原始文本不篡改、不删减、不强制通用转换，保留古籍原貌
3. **索引仅离线预构建**：线上禁止实时拉取、实时解析、实时索引超大文件，保障系统稳定
4. **GitHub访问规范锁定**：仅允许Range分片按需请求，禁止全量拉取，规避限流风险
5. **学术数据严谨性锁定**：不杜撰史料、不臆断人物关系，仅采用公开权威学术数据源
6. **永久非商用公益属性**：永不新增付费、会员、广告、流量变现等商业化模块
