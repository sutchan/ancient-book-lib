# 古籍通｜5GB超大TXT古籍文件 存储+检索+数据库体积变化专项分析

**核心结论前置**：**原始5GB TXT入库一定会膨胀、不会压缩**；合理架构下「源文件不入库、仅索引结构化入库」，最终数据库体积可控在 **300MB–800MB**，实现极速检索、无体积爆炸、可稳定部署。

## 一、核心问题：5GB TXT 存入数据库是膨胀还是压缩？

### 1.1 原始文本直接入库（错误方案）

若将整本 TXT 原文直接存 SQL / SQLite / JSON 字段：

- **体积结果：严重膨胀（1.8～2.5倍）**
- 原始纯文本：5GB
- 数据库存储后：**9GB～12GB**

**膨胀原因（关键）**：

1. 数据库会额外存储：字段类型标记、行尾校验、索引指针、事务日志、页对齐空位
2. 超长文本切片存储会产生大量页碎片
3. 繁体、异体字、UTF8 古文字在数据库字段中占用字节高于原生TXT
4. 默认索引、主键、事务机制持续放大体积

### 1.2 带全文索引入库（更糟糕）

如果存入原文 + 开启全文检索索引：

**最终体积：原始的 3～4 倍**（5GB → 15GB～20GB）

原因：全文索引会拆分每一个字词、存储词频、位置偏移、分词倒排表，文本库索引体积远大于源文件。

### 1.3 正确结论（已写入PRD技术规范）

- **纯原文入库：必然膨胀，无压缩**
- **绝对不允许整本大体积TXT存入数据库**
- 项目正确策略：**文件静态托管 + 结构化索引入库 + 文本懒加载**

## 二、为什么5GB古籍TXT不能直接入库？（项目专属痛点）

本项目古籍文件特征：

- 大量**单文件超大体积**（医藏、史藏单本数百MB）
- 文本密集、无空行、古文字密集、重复典故多
- Next.js 静态部署、Vercel/轻量化服务器**磁盘与构建资源有限**

一旦直接入库会导致三大致命问题：

1. **构建超时**：SSG构建遍历超大文本直接OOM、构建失败
2. **检索卡顿**：数据库全文检索遍历亿级字符，前端秒开失效
3. **体积爆炸**：托管空间爆满、无法正常迭代部署

## 三、5GB资源 最优管理架构

采用**「源文件静态存储 + 结构化轻索引」分离架构**

### 3.1 文件层：原始TXT永久静态托管（不进数据库）

- 所有 .txt 源文件存放于静态资源目录 /public /assets 或对象存储
- 保留完整原版、繁简原文、不压缩、不转码、不丢失古字
- 支持懒加载分片读取，前端按需拉取章节文本

优势：**源文件体积保持5GB，无任何膨胀、零数据库冗余**

### 3.2 索引层：只存「检索索引+元数据」，不存原文

- 馆藏分类（儒/道/医/史…）
- 书籍标题、卷名、章节名
- 文件路径、分片地址、章节偏移量
- 关键词索引、分词倒排索引（精简版）
- 关联人物ID、朝代、标签

**索引最终可控体积：300MB–800MB**

## 四、检索架构优化

### 4.1 摒弃传统数据库 LIKE 模糊检索

超大文本使用数据库模糊匹配会直接超时，完全不适用。

### 4.2 项目专属检索方案（PRD已录入）

1. **预构建离线索引**：开发阶段批量对5GB文本做分词、索引、权重排序，生成轻量化 json/ndx 索引文件
2. **前端内存检索**：用户检索时加载索引，前端完成匹配，无需查大库，实现毫秒级检索响应
3. **章节分片定位**：索引记录每章文本偏移位置，检索命中后**按需加载片段**

## 五、文件分层管理策略

### 5.1 三级分片管理规则

- **一级：馆藏分类文件夹**（十大藏库）
- **二级：书籍目录**（单本全书）
- **三级：自动分片章节文件**（核心优化）

将超大整本TXT自动拆分为「单章节小文件」，解决移动端加载超时、内存溢出。

### 5.2 加载策略

- 目录列表 SSG 静态预渲染
- 章节内容 懒加载+分片加载
- 检索结果 索引匹配+片段预览

## 六、体积变化最终对比总结

| 存储方案 | 原始体积 | 处理后体积 | 优劣 |
|-|-|-|-|
| 整本TXT直接入库 | 5GB | 10GB～20GB（严重膨胀） | ❌ 不可用、构建崩溃、检索极慢 |
| 源文件静态托管+轻索引入库 | 5GB | 源5GB + 索引0.5GB | ✅ 体积可控、检索极速、部署稳定 |

## 七、技术规范（已写入PRD定稿）

1. **禁止将原始古籍TXT文本存入数据库**，所有源文件采用静态文件托管，保持原生体积不膨胀
2. 仅存储书籍元数据、章节索引、路径映射、人物关联数据，实现轻量化存储
3. 超大文本采用**离线预索引+分片懒加载**方案，解决5GB级文献检索与加载性能问题
4. 所有大文件自动章节拆分，适配移动端与SSG静态构建限制
