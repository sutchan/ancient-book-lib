# 古籍通 AncientBook｜版本迭代管理规范

**文档版本**：V1.0 正式定稿

## 1. 版本节奏

- **V1.0**：基础上线稳定版（只读、检索、阅读、考据、下载）
- **V1.1**：体验增值版（收藏、批注、精细化导出、名句典故库）
- **V1.2**：国学学习版（考点、背诵、专题、字词深度解析）
- **V1.3**：学术深化版（图谱、校勘、朝代风貌、词汇演变统计）
- **V1.4**：AI智能研读版（前端离线AI辅助）

## 2. 迭代规则

- 每次迭代必须更新文档、任务清单、版本日志，保证文档与代码完全同步
- 每个版本必须有明确的功能范围、验收标准、性能指标
- 版本发布走 Git 分支流程：dev 合并至 main，打 tag（v1.0.0 语义化版本）

## 3. 版本验收标准要求

每个版本交付前必须明确：

- 功能验收标准（每个功能模块的完成度定义）
- 性能指标（首屏≤1s、检索20–80ms等）
- 兼容性标准（多终端、多浏览器）
- Bug等级准入标准（无P0/P1级缺陷）

## 4. 版本日志

每个版本更新 CHANGELOG：

```plain
## [v1.0.0] - 2026-xx-xx
### 新增
- ...
### 修复
- ...
### 优化
- ...
```

## 5. 版本回滚

- 纯静态架构回滚成本极低，回退到上一个 tag 即可
- 紧急 bug 从 main 拉 fix 分支，修复后合并回 main + dev
