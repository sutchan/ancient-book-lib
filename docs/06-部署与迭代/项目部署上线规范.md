# 古籍通 AncientBook｜项目部署上线规范

**文档版本**：V1.2（新增 GitHub Pages CI/CD 与自定义域名章节，适用产品版本 v1.0.5）

## 1. 部署方式

优先 Vercel 静态一键部署，支持任意静态服务器托管（Nginx、GitHub Pages、私有服务器等）。

## 2. 部署流程

```bash
# 1. 安装依赖
npm install

# 2. 静态构建
npm run build

# 3. 本地静态预览验证
npm run start

# 4. 部署（Vercel）
vercel --prod
```

## 3. 部署前置检查

- 全站合规内容补齐：开源协议、数据来源、非商用声明、免责条款完整公示
- 隐私合规：不收集个人身份信息；匿名访问统计（GA4）已在合规声明中明示且开启 IP 匿名化
- 静态索引资源已提交仓库（src/static-index/）
- 无任何动态接口、数据库依赖

## 4. 上线验收标准

- 无构建报错、无资源404、无接口异常
- 全功能闭环可用（浏览、检索、双语阅读、分片加载、考据、下载）
- 性能指标全部达标：首屏≤1s、检索20–80ms
- 合规公示完整
- 多终端、多浏览器兼容正常
- 统计验证：访问任意页面后，Google Analytics 后台（`G-H76XG9L6FZ`）实时概览出现页面浏览记录（通常 1–5 分钟延迟）

## 5. 部署流水线（CI/CD）

### 5.0 生产站点现状

- 线上地址：**https://guji.ewuse.com/**（DNS 为多 A 记录智能解析，响应头 `server: edgeone makers`）
- 托管平台：腾讯云 **EdgeOne Pages**，由其从 Git 仓库拉取并构建 `out/` 产物，国内访问速度优
- GitHub Actions（`.github/workflows/deploy.yml`）自 v1.2.1 起默认只做**质量门禁**：生成索引 → 重建全馆藏索引 → 静态构建 → 单元测试 → 上传 `out/` 产物（`upload-artifact@v4`，保留 7 天）
- GitHub Pages 部署改为**开关式**：仅当仓库变量 `ENABLE_PAGES = true` 时才执行 `upload-pages-artifact` + `deploy-pages`；
  默认关闭，避免仓库未启用 Pages 时持续报
  `Failed to create deployment (status: 404)`（该报错含义仅为「该仓库未启用 Pages 站点」，与代码无关）
- 需要 Pages 备用站点时：先按 §5.1.1 启用 Pages，再添加仓库变量 `ENABLE_PAGES = true`

### 5.1 GitHub Pages 部署（默认关闭，按需开启）

如需恢复 Pages：在 `.github/workflows/deploy.yml` 增加 `upload-pages-artifact@v3`（path `./out`）与
`actions/deploy-pages@v4` 两个步骤，并给 workflow 授予 `pages: write`、`id-token: write` 权限。

#### 5.1.1 首次启用（必须手动操作一次）

仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
未启用或 Source 仍是「Deploy from a branch」时，部署会直接失败：

```
Error: HttpError: Not Found
Error: Failed to create deployment (status: 404)
Ensure GitHub Pages has been enabled
```

> 该 404 与代码、产物、权限均无关，只表示「该仓库尚未启用 Pages 站点」，必须在仓库设置页开启。

校验是否启用：`GET https://api.github.com/repos/sutchan/ancient-book-lib/pages`，返回 404 即未启用。

#### 5.1.2 绑定自定义域名（启用 Pages 时必做）

Pages 默认地址为 `https://sutchan.github.io/ancient-book-lib/`（带仓库名子路径），
而全站链接与静态资源均为根路径（`/`、`/images/logo.png`），子路径下会全部 404。
因此启用 Pages 时**必须绑定自定义域名**使站点位于根路径：

> 注意：生产域名 `guji.ewuse.com` 当前解析至 EdgeOne。若改指 GitHub Pages，会中断现有生产站点且国内访问变慢，
> 仅在确实要迁移时才执行；建议 Pages 仅作备用镜像、使用其默认域名。

1. DNS 解析：添加 `CNAME` 记录指向 `sutchan.github.io`（根域名用 `ALIAS`/`ANAME`，或 `A` 记录指向
   `185.199.108.153 / 185.199.109.153 / 185.199.110.153 / 185.199.111.153`）。
2. 仓库配置变量：Settings → Secrets and variables → Actions → Variables → New repository variable
   名称 `PAGES_CUSTOM_DOMAIN`，值填域名（如 `guji.example.com`）。
   workflow 会在构建后自动写入 `out/CNAME`，无需改动代码；未配置该变量则跳过、使用默认域名。
3. Settings → Pages → Custom domain 填入同一域名，勾选 **Enforce HTTPS**（证书签发需等待数分钟）。

> 也可直接在 Settings → Pages 填域名而不配变量，但下次部署可能因缺少 CNAME 被重置；推荐两者一致。

#### 5.1.3 访问路径与托管选择

- **推荐**：EdgeOne Pages / Vercel / Nginx 等根路径静态托管（当前生产为 EdgeOne + `guji.ewuse.com`）；
- 或：自定义域名 + GitHub Pages（根路径，代码零改动）；
- 不推荐：强行适配子路径（需设 `basePath` 并批量改造全部硬编码链接，易遗漏）。

#### 5.1.4 其他注意事项

- `public/.nojekyll`：禁用 Jekyll，防止 `_next/` 等下划线目录被忽略导致资源 404。
- Node 20 弃用警告（`DEP0040 punycode`）来自 action 运行时，属无害提示，待官方 action 升级后自动消失。
- PR 触发仅执行构建校验，不上传产物、不部署；`concurrency.cancel-in-progress: false` 避免部署被并发任务取消。

## 6. 上线后运维

- 纯静态架构零运维成本，无需备份、迁移、数据库维护
- 资源更新仅需重新构建索引并提交部署
- 监控访问日志，观察GitHub分片请求限流情况
