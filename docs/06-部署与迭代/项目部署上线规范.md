# 古籍通 AncientBook｜项目部署上线规范

**文档版本**：V1.1（新增 GitHub Pages CI/CD 部署章节，适用产品版本 v1.0.4）

## 1. 部署方式

优先 Vercel 静态一键部署，支持任意静态服务器托管（Nginx、GitHub Pages、私有服务器等）。

## 2. 部署流程

```bash
# 1. 安装依赖
npm install

# 2. 静态构建
npm run build

# 3. 本地静态预览验证
npm run start

# 4. 部署（Vercel）
vercel --prod
```

## 3. 部署前置检查

- 全站合规内容补齐：开源协议、数据来源、非商用声明、免责条款完整公示
- 隐私合规：不收集个人身份信息；匿名访问统计（GA4）已在合规声明中明示且开启 IP 匿名化
- 静态索引资源已提交仓库（src/static-index/）
- 无任何动态接口、数据库依赖

## 4. 上线验收标准

- 无构建报错、无资源404、无接口异常
- 全功能闭环可用（浏览、检索、双语阅读、分片加载、考据、下载）
- 性能指标全部达标：首屏≤1s、检索20–80ms
- 合规公示完整
- 多终端、多浏览器兼容正常
- 统计验证：访问任意页面后，Google Analytics 后台（`G-H76XG9L6FZ`）实时概览出现页面浏览记录（通常 1–5 分钟延迟）

## 5. GitHub Pages 部署（CI/CD）

部署流水线见 `.github/workflows/deploy.yml`：`main` 推送 → 构建（生成索引 → `next build` → 单元测试）→ 上传 `out/` 产物 → `actions/deploy-pages@v4` 发布。

### 5.1 首次启用（必须手动操作一次）

仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
未启用或 Source 仍是「Deploy from a branch」时，部署会直接失败：

```
Error: HttpError: Not Found
Error: Failed to create deployment (status: 404)
Ensure GitHub Pages has been enabled
```

> 该 404 与代码、产物、权限均无关，只表示「该仓库尚未启用 Pages 站点」，必须在仓库设置页开启。

校验是否启用：`GET https://api.github.com/repos/sutchan/ancient-book-lib/pages`，返回 404 即未启用。

### 5.2 访问路径约束（重要）

Pages 默认地址为 `https://sutchan.github.io/ancient-book-lib/`（带仓库名子路径），
而全站链接与静态资源均为根路径（`/`、`/images/logo.png`），子路径下会全部 404。二选一：

- **推荐**：Pages 绑定自定义域名（Settings → Pages → Custom domain），站点位于根路径，代码零改动；
- 或：改用 Vercel / Nginx 等根路径静态托管；
- 不推荐：强行适配子路径（需设 `basePath` 并批量改造全部硬编码链接，易遗漏）。

### 5.3 其他注意事项

- `public/.nojekyll`：禁用 Jekyll，防止 `_next/` 等下划线目录被忽略导致资源 404。
- Node 20 弃用警告（`DEP0040 punycode`）来自 action 运行时，属无害提示，待官方 action 升级后自动消失。
- PR 触发仅执行构建校验，不上传产物、不部署；`concurrency.cancel-in-progress: false` 避免部署被并发任务取消。

## 6. 上线后运维

- 纯静态架构零运维成本，无需备份、迁移、数据库维护
- 资源更新仅需重新构建索引并提交部署
- 监控访问日志，观察GitHub分片请求限流情况
