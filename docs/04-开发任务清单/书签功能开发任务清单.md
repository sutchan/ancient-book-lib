**规划版本**：v1.14.3（待开发，未实现）
**对应需求**：为读者提供跨会话的「书签」能力，贴合纯静态 / 零后端 / `localStorage` 持久化架构
**状态**：规划中（任务清单，尚未编码）
**制定日期**：2026-09-13

## 一、范围与形态

书签包含两种形态，建议分阶段落地：

| 形态 | 含义 | 与现有能力区别 |
|---|---|---|
| **A. 书籍收藏（我的书架）** | 用户主动把某部书加星，跨会话长期保存 | 区别于「最近阅读」`ab-recent`（自动记录、仅最近 10 本）；收藏是**有意识的持久子集** |
| **B. 阅读位置书签** | 在读书内保存多个「锚点」（第 X 章第 Y 页），随时跳回 | 区别于自动进度 `ab-remote-${bookId}`（只记**最后一次**位置） |

**建议**：先做 A（MVP，风险最低），B 作为增强。

## 二、架构约束（必须遵守）

- 纯静态 SSG，无 DB / 无后端：所有书签仅存 `localStorage`，**禁止**引入服务端存储或网络同步。
- 跨设备同步方案：提供「导出 / 导入书签 JSON」文件按钮（无服务器），契合隐私与零后端定位。
- 所有书签 UI 须为 `"use client"`，并在 `useEffect` 后渲染，避免 SSG/CSR hydration 不一致（参考 `components/RecentBooks.tsx`）。
- 不新增运行时依赖（仓库当前零状态库）；跨组件实时同步用极简 `subscribe/notify` pub/sub 实现，避免引入 Zustand 等。

## 三、数据模型

```ts
// 书籍收藏
interface Bookmark { id: string; title: string; category: string; time: number }

// 阅读位置书签（B 阶段）
interface ReadPosBookmark { chapterIdx: number; pageIdx: number; label: string; createdAt: number }
```

`localStorage` key 约定：

- 书籍收藏：`ab-bookmarks`（JSON 数组）
- 阅读位置（按书隔离）：`ab-pos-${bookId}`（JSON 数组）

## 五、验收标准

- `npx tsc --noEmit` 0 错误 · `npm test` 全绿（含新增书签用例）
- 书签在刷新 / 重开浏览器后仍保留；导航角标、书签页、阅读页星标状态实时一致
- 不参与服务端渲染，无 hydration 警告；不新增依赖、不引入后端
- 语义化 `id` 齐备（`nav-bookmarks`、`bookmark-toggle-${id}` 等），便于无障碍与测试定位

## 六、风险与注意

- 现有 `ab-recent`（最近阅读）与书签并存，UI 上须明确区分两者语义，避免用户混淆
- 阅读位置书签若与自动进度并存，需明确「自动恢复上次位置」与「手动书签跳回」的优先级
- 遵循仓库「每次修改 bump 最小版本」规则，仅更新被改文件头注释，禁止全仓批量刷写
- 阅读页星标切换需同步更新 `ab-bookmarks`，并触发 pub/sub 通知导航角标与书签页刷新
