# 古籍通 AncientBook｜Git 分支与代码提交规范

**文档版本**：V1.0 正式定稿

统一团队版本管理、分支流转、提交信息规范，保证仓库整洁、迭代可追溯、回滚可控。

## 1. 固定分支体系（长期不变）

- **main（主分支）**：线上稳定上线代码，仅合并、不直接推送、不随意修改，对应生产环境
- **dev（开发分支）**：日常迭代开发主分支，所有功能开发基于该分支拉出
- **feature/\*（功能分支）**：单功能开发分支，格式：feature/功能名
- **fix/\*（修复分支）**：bug 修复分支，格式：fix/问题描述

## 2. 分支流转规则

1. 从 dev 拉出 feature 分支进行功能开发
2. 自测完毕后合并回 dev 分支
3. 版本迭代完成、整体自测通过，dev 合并至 main 上线
4. 线上紧急 bug 从 main 拉 fix 分支，修复后合并回 main + dev

## 3. Commit 提交信息规范（强制）

统一格式：**type: 简要描述（不超过20字）**

- **feat**：新增功能
- **fix**：缺陷修复
- **style**：样式、排版、交互微调
- **docs**：文档变更
- **refactor**：重构（不改变功能）
- **perf**：性能优化
- **build**：构建配置变更
- **chore**：杂项维护

示例：

```bash
feat: 新增繁简切换功能
fix: 修复检索高亮错位问题
docs: 更新PRD终审文档
```

## 4. 提交前检查

- 代码必须通过 lint 与类型检查
- 禁止提交 console.log 调试代码
- 禁止提交敏感信息、密钥、token
- 每次迭代必须同步更新文档、任务清单、版本日志

## 5. 版本标签

- 每个上线版本打 tag：v1.0.0、v1.1.0 格式
- 版本号遵循语义化版本规范（主版本.次版本.修订号）
