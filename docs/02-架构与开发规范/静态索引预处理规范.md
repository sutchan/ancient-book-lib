# 古籍通 AncientBook｜静态索引预处理规范

**文档版本**：V1.0 正式定稿
**适配代码版本**：v1.3.6　**最近校订**：2026-09-08

> **现状对齐（v1.3.6）——实际构建脚本与本规范差异（以本节为准）**：
> - **书目索引**：`npm run build:catalog`（`scripts/build-daizhige-catalog.mjs`）调 GitHub Trees API 遍历 `garychowcmu/daizhigev20`，生成 `public/index/daizhige-catalog.json`（15,694 部，5.7MB，**入库**）。
> - **全文索引 + 章节偏移**：`npm run build:fulltext`（`scripts/build-fulltext-index.mjs`，需下载上游 4.9GB TXT）在同一次 pass 生成 `public/index/fulltext-index.json` 与 `chapters.json`；二者**体积过大已 gitignore，构建期生成、不入库**。
> - **不再有 `src/static-index/` 与「按馆藏拆分的 ru/yi/shi.json」**：v1.3.0 起改为上述两份产物 + 单一目录索引；`public/index/` 下的 `inverted-index.json`、`chunk-manifest.json` 为 v1.0 时代遗留、当前代码已不引用。
> - 未生成全文索引时检索自动回退「标题检索」，站点功能不受影响。

## 1. 预处理执行时机

仅在本地开发、版本资源更新或 CI 构建期执行，线上运行时绝不执行。

## 2. 强制处理标准

### 2.1 文本分块

- 单块大小：2–4KB/块（古籍文本最优粒度）
- 按章节、卷次、段落自动切分，优先语义截断
- 每一块生成唯一ID、归属书籍、归属馆藏、字节偏移位置
- 不破坏古文语义段落结构

### 2.2 倒排索引构建

- 索引结构：仅存储词条、权重、位置、字节偏移、文件路径
- **不存原文**，极致瘦身
- 索引最终体积：300–700MB
- 词频权重、匹配类型（标题/章节/正文）固化

### 2.3 繁简映射固化

- 固化古籍专属字库，覆盖古字、异体字、避讳字
- 覆盖官职、年号、古地名、专有名词转换规则
- 繁体原版零转换、简体对照保真无丢失
- 繁简双向映射，支持简体输入匹配繁体原文

### 2.4 索引拆分

- 按十大馆藏独立拆分：ru.json（儒藏）、yi.json（医藏）、shi.json（史藏）等
- 支持按需懒加载，控制前端内存占用
- 兼容低配设备流畅访问

## 3. 预处理输出

- 轻量化静态索引池（总体300–700MB）
- 提交至项目代码仓库（src/static-index/）
- 线上永久静态复用，无动态计算

## 4. 更新机制

- 上游GitHub古籍资源更新时：本地重新执行分块+索引脚本
- 更新静态索引文件，直接提交仓库部署
- 线上服务零停机、零重构、无数据迁移成本
