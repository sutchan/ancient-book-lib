# 人物考据模块规格（Character Dossier）

> 适用版本：v1.13.2 起 ｜ 状态：实现中
> 关联页面：`/character`（人物考据）· `/people`（人物库）· `/people/detail` · `/relation`
> 数据来源：CBDB 中国历代人物传记资料库（`cbdb-project/cbdb_sqlite`，2026-09-05 版，661,350 人，CC BY-NC-SA 4.0）

---

## 1. 模块定位

「人物考据」不是「人物库」的副本，两者的职责边界如下：

| | /people 人物库 | /character 人物考据 |
|---|---|---|
| 入口逻辑 | **人名/姓氏/朝代浏览**，回答"有没有这个人" | **输入人名 → 析出候选 → 生成一份可研判的档案**，回答"这个记载可信吗、是他吗" |
| 数据视角 | CBDB 原始索引（按姓氏分片、按人名命中） | 归一化的 **CharacterProfile**（六维分面聚合） |
| 关键能力 | 全量浏览、分页、繁简/别名检索 | 重名消歧、档案完整度、数据矛盾校验、馆藏与关系联动 |
| 输出物 | 列表 + 详情页 | 一份带**校验结论**的考据档案 |

一句话：人物库是**索引入口**，人物考据是**研判工作台**。考据页在内部复用人物库的 CBDB 索引，不另建数据源。

## 2. 改造前的现状与待改进点

### 2.1 已有核心能力

- CBDB 全量 Person 索引：`/index/cbdb/meta.json` + `surnames/*.json` + `search.json`；紧凑元组 `[id, 姓名, 拼音, 生年, 卒年, 指数年, 性别, 朝代, 籍贯]`。
- 人名检索：`lib/cbdb.ts#searchPersons`，四级优先级（姓名前缀 > 姓名子串 > 别名前缀 > 别名字串），繁简双向兼容。
- 六个事实分面：字號別名（ALTNAME）、科舉入仕（ENTRY）、任职（POSTED_TO_OFFICE）、史料來源（BIOG_SOURCE）、亲属/社会关系（KIN/ASSOC）、著作（PERSON_TEXT）——全部已由构建脚本产出分片 JSON。
- 陈列层：`RelationGraph`（放射状 SVG 关系图）、`PersonTimeline`（生卒/科举/任职时间轴）。

### 2.2 改造前 `/character` 的问题

| # | 问题 | 影响 |
|---|---|---|
| P1 | 只读 `characters.json`（28 位种子），与 66 万人的 CBDB 索引**完全脱钩** | 考据页实际只能看到 28 人，且 `native/office/death` 大量为空 |
| P2 | 无"同名冲突"处理 | CBDB 中重名极多（如「李白的同名录」），检索直接返回列表不做区分引导，用户无法判断"哪一个才是" |
| P3 | 无任何**数据校验** | 把缺失字段与推算字段（指数年）当作事实呈现；生卒倒挂、登科晚于卒年等脏数据直接上线 |
| P4 | 无档案详情视图 | 只有一张卡片，不能展开生卒、科举、任职、关系、史料 |
| P5 | 关联展示薄弱 | 关系对象不可点击跳转；著作与本站馆藏（殆知阁 v20）无联动 |
| P6 | 加载失败无降级 | CBDB 索引未部署时页面整块空白 |
| P7 | 状态不进 URL | 选中人物无法分享链接、无法前进后退 |

### 2.3 本次纳入范围 vs 明确不做

**做**：契约层归一化 · 规则化数据校验 · 完整度评分 · 重名消歧 · 档案视图 · 关联联动（馆藏检索/关系跳转/外链）· URL 状态同步 · 加载失败降级 · 单元测试。

**不做**（避免架构红线冲突）：不引数据库/后端；不新增 npm 依赖；不复刻 `/people` 的浏览与分页；不做关系推理推断（仍由 `/relation` 的 BFS 溯源负责）；不修改 CBDB 上游数据本身，只在展示层标注问题。

## 3. 功能范围

### F1 检索
- 输入：任意人名/字号/别名片段（繁简皆可）。
- 处理：300ms 防抖 → `searchPersons(kw, 20)` → 去重（同 id 合并）→ `pickDistinguishers` 计算区分维度。
- 输出：`CandidateHit[]` + `Distinguisher[]`；0 条时给"换字号或别名再试"的建议。
- 超长输入（> 50 字）截断后检索，避免无意义的全表扫描。

### F2 档案生成（`loadCharacterProfile`）
- 并发拉取六个分面，**任一分面失败不影响其余**（`Promise.allSettled`），归档到 `facets` 状态位。
- 找不到 ID 时 reject 并由 UI 转为用户可读文案。

### F3 数据校验（`validateCharacterProfile`）
- 三类严重度：**error**（数据自相矛盾，档案不可直接引用）/ **warn**（量程存疑或关键字段缺失）/ **info**（仅提示丰度不足）。
- 固定 code，便于 UI 映射与后续做构建期批量体检。
- 完整度评分：11 个加权维度 → 0–100 分 → AAA/AA/A/B/C 五档。

| code | 级别 | 含义 |
|---|---|---|
| `NAME_MISSING` | error | 姓名缺失 |
| `BIRTH_DEATH_INVERTED` | error | 卒年早于生年 |
| `YEAR_OUT_OF_RANGE` | error | 年份越出 ±3000/−2500 合理量程 |
| `ENTRY_AFTER_DEATH` | error | 登科年份晚于卒年 |
| `ENTRY_BEFORE_BIRTH` | error | 登科年份早于生年 |
| `LIFE_MISSING` | warn | 生卒俱缺 |
| `LIFESPAN_IMPLAUSIBLE` | warn | 寿命 > 120 或 < 10 |
| `OFFICE_YEAR_OUT_OF_LIFE` | warn | 任职年份越出生卒区间 |
| `INDEX_YEAR_OUT_OF_LIFE` | warn | 指数年不在生卒区间内 |
| `DYNASTY_MISSING` | warn | 朝代缺失 |
| `FACET_FAILED` | warn | 某一维度数据加载失败（已降级为空） |
| `INDEX_YEAR_MISSING` | info | 无指数年 |
| `NATIVE_PLACE_MISSING` | info | 籍贯失载 |
| `ALTNAME_MISSING` | info | 无字号别名 |

### F4 关联展示
- 亲属/社会关系 → 点击跳 `/people/detail?id=`。
- 著作标题 → `/search?q=<title>&mode=title` 在馆藏检索版本。
- 姓名 → `/relation?name=<name>` 关系溯源、`/search?q=<name>&mode=full` 全文检索。
- CBDB 官方档案外链。
- 有关系数据时渲染 `RelationGraph`。

## 4. 数据契约

### 4.1 输入

| 输入 | 来源 | 形态 |
|---|---|---|
| 人名关键词 | 用户输入 | `string` |
| CBDB 人物元组 | `findPersonById` | `CbdbPerson`（9 元数组，`0` 表示缺失，负数为公元前） |
| 六维分面 | `getPersonXxx(id)` | 结构化数组，任一可为 `null`/`[]` |
| 遗留种子 | `public/index/characters.json` | `Character`（v1.4.3 契约，`id` 形如 `cbdb-439127`） |

### 4.2 输出：`CharacterProfile`

```
CharacterProfile
├── id / generatedAt / source{name,url,releaseDate,license}
├── identity  {id, name, nameSimplified, pinyin, gender, dynasty, indexYear}
├── life      {birthYear, deathYear, lifespan}        // 一律 number | null，0 归一化为 null
├── nativePlace
├── altnames[] {name, type}
├── entries[]  {entry, year, rank}
├── offices[]  {office, firstYear, lastYear, appt}
├── texts[]    {title, role, year}
├── kin[]      {id, name, rel}
├── assoc[]    {id, name, rel, year}
├── sources[]  string
└── facets     Record<FacetKey, {key, status: ok|empty|error, error?}>
```

分面状态语义（**关键**）：

| status | 含义 | UI |
|---|---|---|
| `ok` | 分面已加载且有数据 | 正常渲染 |
| `empty` | 分面已加载，CBDB 确实无记录 | 显示"CBDB 暂无此维度记录" |
| `error` | 分面加载失败 | 显示降级提示 + 计入 `FACET_FAILED` warn |

> 区分 `empty` 与 `error` 是本模块的核心设计：**不能把"加载失败"粉饰成"暂无记录"**，否则用户会误以为史料本身缺失。

### 4.3 输出：`CharacterValidation`

```
CharacterValidation
├── issues[]        {code, severity, field, message, hint?}
├── hasError        boolean            // 是否含 error 级
└── completeness    {score, grade, dimensions[{key,label,weight,hit}]}
```

完整度权重（合计 **100**，各维度相对轻重保持稳定，修改时必须保证合计仍为 100；代码侧已对 score 做 `0–100` 防御性夹取）：

| 维度 | 权重 | 命中条件 |
|---|---|---|
| `name` 姓名 | 10 | 非空 |
| `life` 生卒年 | 16 | 有两端记满，**只有一端按半量折算（8 分）** |
| `indexYear` 指数年 | 5 | 有值 |
| `dynasty` 朝代 | 9 | 非空 |
| `nativePlace` 籍贯 | 9 | 非空 |
| `altnames` 字號別名 | 8 | 非空数组 |
| `entries` 科举/入仕 | 8 | 非空数组 |
| `offices` 任职 | 9 | 非空数组 |
| `texts` 著作 | 12 | 非空数组 |
| `sources` 史料来源 | 4 | 非空数组 |
| `relations` 亲属/社会关系 | 10 | kin 或 assoc 任一非空 |

等级：`>=85 AAA`、`>=70 AA`、`>=55 A`、`>=35 B`、其余 `C`。

> UI 展示请以 `completeness.score` 为准，**不要自行把 `dimensions` 的 `weight` 相加**：`life` 维存在半量折算，加权和与 score 不相等。

## 5. 交互边界

### 5.1 URL 约定（`app/character`）

| 参数 | 类型 | 说明 |
|---|---|---|
| `q` | string | 检索关键词，防抖后写回 |
| `id` | number | 当前选中的 CBDB personid |

- state → URL 用 `router.replace(..., { scroll: false })`（不污染历史栈）；URL → state 由 `useSearchParams` 反向同步，两边保持幂等。
- `id` 非法（NaN/≤0/超范围）→ 忽略并回退到搜索态，不报错。

### 5.2 异步边界

- 每次检索带 `cancelled` 守卫，**旧请求结果不得覆盖新输入**。
- 组件卸载必须清理定时器与未完成的 setState。
- `loadProfile` 失败 → 错误卡片 + "返回搜索"，不整页崩溃。

### 5.3 降级边界

`loadCbdbMeta()` 失败（索引未部署/离线）→ 工作台整体让位给遗留 `CharacterList`（28 位精选种子），并显式提示"CBDB 全量索引不可用，当前展示精选人物档案"。
**任何部署形态下 `/character` 都必须有可读内容。**

### 5.4 署名边界

CBDB 数据以 CC BY-NC-SA 4.0 授权。凡渲染其派生内容的页面，必须同时给出：数据名称、版本日期、许可协议、原始链接。缺失即违反署名要求。

## 6. 边界情况清单

| 场景 | 期望行为 |
|---|---|
| 输入只含空格/标点 | 视为空查询，不做检索，不报错 |
| 输入 > 50 字 | 截断后检索 |
| 检索返回同 id 多条 | 按 id 去重，保留首次命中 |
| 检索到多个同名人物 | 提示可按朝代/活动时段/籍贯区分，逐条展示区分值 |
| `searchPersons` reject | 候选区显示错误提示，保留输入框内容 |
| `loadCharacterProfile` reject（找不到人） | 错误卡片 + 返回搜索 |
| 分面加载失败 | 该分面置 `error`，其余照常渲染，计入 `FACET_FAILED` |
| 关系对象姓名映射缺失 | 回退显示 `人物 <id>`，链接仍可点 |
| 生卒俱缺 | `LIFE_MISSING` warn + 档案显示"生卒年不详"，引用指数年时注明是推算值 |
| 公元前年份（负年） | 统一格式化为"公元前 N 年"，参与所有比较运算 |
| 指数年缺失或落在生卒区间外 | `INDEX_YEAR_MISSING` info / `INDEX_YEAR_OUT_OF_LIFE` warn |
| CBDB 索引整体不可用 | 降级到 28 位精选种子 |
| 全部六个分面为空 | 档案仍可读（身份 + 校验结论），每区块给具体空态文案，不用统一"暂无数据" |
| 移动端窄屏 | flex 换行 + `minmax` 网格，不做横向滚动 |
